# Édito (planning éditorial des réseaux sociaux)

- App locale mono-utilisateur, sans authentification. Interface et textes en français (tutoiement). Nom du produit dans `src/lib/product.ts` ; la marque gérée est le nom de l'espace de travail (`meta.ai.brand.name`).
- Espaces de travail : liste lue dans `workspaces.json` (racine, ignoré par git, modèle `workspaces.example.json`, schéma dans `src/lib/workspaces.ts`, lecture `listWorkspaces` dans `src/server/workspace.ts`) ; sans ce fichier, un seul espace « Ma marque » (`data/marque.db`, `brand/MARQUE.md`). Une base SQLite par espace dans `data/`, médias partagés dans `data/uploads`. Espace ouvert mémorisé dans `data/workspace.json`, `getDb()` renvoie la base de l'espace ouvert ; sélecteur en tête de la barre latérale (`meta.workspaces`, action `switchWorkspace`). Premier lancement d'un espace : piliers, brief et charte de sa config (`seedWorkspace`), connexion LM Studio du premier espace. Données perso (`data/`, `brand/` sauf README/EXEMPLE/skills, `workspaces.json`) jamais committées.
- Données : SQLite via Drizzle (`src/db/schema.ts`). Après une modification du schéma, lancer `npm run db:generate` et committer la migration générée dans `drizzle/` (appliquée automatiquement au démarrage, sur chaque base).
- Le layout `src/app/(app)/layout.tsx` charge colonnes/piliers/campagnes et posts une seule fois ; les vues les lisent via `useApp()` (`src/components/app-provider.tsx`, qui ouvre aussi la fiche d'un post et la fenêtre « Idées »).
- Coquille dans `src/components/shell/` : barre latérale repliable (cookie `sidebar`), menu mobile, bouton « Créer », palette ⌘K, raccourcis (`N`, `/`, `1`-`3`, `?` ; liste dans `shortcuts.tsx`) ; entrées du menu dans `nav.ts`. En-têtes : `PageHeader`/`PageBody` (`src/components/page-header.tsx`) et `PlanningHeader` pour Tableau / Calendrier / Liste (`src/components/planning/`), dont les filtres vivent dans l'adresse (`usePostFilters`, `history.replaceState`). Pages Marque sous `/brand` (anciennes adresses `/library/*` et `/accounts` redirigées dans `next.config.ts`).
- Accueil (`/home`, `src/components/home/`) : « Bien démarrer » (`onboardingSteps` dans `src/lib/onboarding.ts`, masquable via `ui.onboardingDismissed`), à traiter (`homeTodos` dans `src/lib/home.ts`), semaine en cours, rythme par réseau, avancement, comptes. Calendrier : ajout express sur un jour, tiroir « Non planifiés » et agenda en mobile. Liste : statut et date modifiables dans la ligne, regroupement, export CSV. Barre de sélection partagée : `src/components/planning/bulk-bar.tsx`.
- Réglages en sections (`src/app/(app)/settings/`) : Workflow (colonnes avec leur rôle, piliers, campagnes), Assistant IA, Préférences (thème, densité des cartes, page d'arrivée `ui.landing` lue par `src/app/page.tsx`, raccourcis), Données (`src/server/data-info.ts`).
- Thème clair/sombre/système : `data-theme` sur `<html>` (cookie `theme`, `src/lib/preferences.ts`), couleurs dans `src/app/globals.css` (bloc `@variant dark`) ; jetons d'état `success`, `warning`, `info`, `destructive`.
- Les mutations passent par les server actions de `src/server/actions.ts` (qui appellent `revalidatePath("/", "layout")`), sauf l'upload de médias (`src/app/api/posts/[id]/media/route.ts`).
- Réseaux (Instagram, TikTok, YouTube, LinkedIn, Facebook, X), formats et limites : `src/lib/platforms.ts` ; un nouveau réseau demande aussi son logo (`platform-icon.tsx`), sa checklist (`accounts.ts`) et son aperçu (`post-preview.tsx`).
- Kanban (`src/components/board/`) : chaque colonne a un rôle (`columns.kind` : idée, en cours, à valider, planifié, publié, archivé ; `src/lib/columns.ts`) qui pilote le « en retard », le repli par défaut des colonnes terminées et les questions au dépôt (date pour « Planifié », lien pour « Publié »). Retard, libellés de date et « prêt à publier » dans `src/lib/post-status.ts` ; filtres (dont « État ») dans `src/lib/filters.ts`. Densité des cartes et colonnes repliées dans `settings` (clé `ui`, `meta.ui`, `src/lib/preferences.ts`). Brouillon d'un nouveau post : `emptyDraft` (`src/lib/post-draft.ts`).
- Composants UI de base dans `src/components/ui` (style shadcn/ui, écrits à la main sur `radix-ui`, plus `cmdk` et `react-day-picker`) ; logos des réseaux dans `src/components/icons/`.
- Vérifications : `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.
- Assistant IA : modèle local via le serveur LM Studio, ou en ligne via OpenRouter (`ai.provider`, modèle `ai.openrouterModel`, `activeModel`), tous deux en API compatible OpenAI (`/v1/chat/completions` en streaming, `connectionFor` dans `src/server/ai/lmstudio.ts`). Clé OpenRouter rangée à part (clé `secrets` de `settings`, `getOpenRouterKey`), jamais envoyée au navigateur (`meta.openrouterKey` dit seulement si elle existe) ; test et liste des modèles (outils requis, `:free` d'abord) par `POST /api/ai/models`. Prompts, schémas d'entrée/sortie et lecture des réponses (y compris la réflexion `[THINK]`/`<think>` des modèles reasoning) dans `src/lib/ai/` ; appel au modèle dans `src/server/ai/lmstudio.ts` ; route `src/app/api/ai/route.ts` (progression puis résultat en NDJSON) ; réglages (clé `ai` de la table `settings`) lus via `meta.ai`. Analyse des médias d'un post (tâche `mediaAnalysis`) : le navigateur réduit les photos et extrait quelques images des vidéos (`src/components/ai/media-frames.ts`, budget et lecture des capacités des modèles dans `src/lib/ai/media.ts`), envoyées en data URL (`image_url`) ; nécessite un modèle « vision » (capacité lue via `/api/v1/models` de LM Studio, sinon `/api/v0/models`). Document de référence de l'espace (`brand/MARQUE.md` ; source de vérité sur la marque) : relu à chaque demande par `readBrandDoc` (`src/server/brand-doc.ts`), envoyé dans le prompt système via `BrandContext.doc` (limite et nettoyage dans `src/lib/ai/brand-doc.ts`), état affiché dans Marque › Identité via `meta.brandDoc`. Le brief de marque (clé `ai.brand`) se règle dans Marque › Identité (`brand-brief-form.tsx`), la connexion LM Studio dans Réglages › Assistant IA.
- Comptes réseaux : une ligne par réseau dans `social_accounts` (+ `account_checklist_items`), créée au démarrage par `ensureAccounts` (`src/db/seed.ts`) ; lus via `meta.accounts`. Statuts (dont « Non utilisé », qui masque le réseau dans le reste de l'app), types et checklist par défaut dans `src/lib/accounts.ts` ; réseaux proposés via `usedPlatforms` / `platformChoices`, cochés sur un nouveau post via `defaultPostPlatforms` (colonne `default_on_posts`). Le rythme `postsPerWeek` alimente les alertes du calendrier (`isBelowTarget` dans `src/lib/calendar.ts`).
- Bibliothèque : charte graphique dans `settings` (clé `brand`, défaut neutre `DEFAULT_BRAND_KIT` dans `src/lib/brand.ts`, charte de départ d'un espace via `brandKit` de `workspaces.json` et `workspaceBrandKit`, lue via `meta.brand` ; bloc `studio` : couleurs et espacement des titres des nouveaux carrousels) ; tables `library_assets`, `hashtag_groups`, `post_templates` (listes `platforms`/`checklist` stockées en JSON) lues via `meta.library`, `meta.hashtagGroups`, `meta.templates`. Contenu de départ (groupes de hashtags, modèles) créé une seule fois par `seedLibrary` (si `starterLibrary`) (marqueurs `seed:*` dans `settings`). L'assistant reçoit la charte via `BrandContext.kit` (slogan/positionnement partout, charte complète pour la tâche `visualBrief`).
- Studio carrousel (`/studio`, `src/components/studio/`) : table `carousels` (slides `{title, body}` et mise en page stockées en JSON, mockup = image de la bibliothèque, catégorie « mockup »), lue via `meta.carousels`. Données, mise en page du texte (retour à la ligne, réduction pour tenir dans la zone) et défauts dans `src/lib/carousel.ts` ; couleurs d'un nouveau carrousel tirées de la charte (`defaultCarouselStyle`, bloc `studio` : fond sans mockup, titre, texte, accent des mots du titre écrits `*entre astérisques*`), choisies parmi la charte (`meta.brand.palettes`) avec `BrandColorPicker` ; rendu canvas dans le navigateur (`render-slide.ts`), le même pour l'aperçu et l'export PNG. Polices des slides d'après la charte (`meta.brand.fonts`, ex. « Inter ExtraBold » → Inter 800, `resolveSlideFonts` dans `src/lib/slide-fonts.ts`) : Outfit, Plus Jakarta Sans, Inter et Inter Tight fournies par `next/font` (variables `--font-slide-*` du layout racine), les autres cherchées sur l'ordinateur. Export : `prepareCarouselPost` crée le post (format carrousel) ou renvoie ses médias à remplacer, puis upload via `/api/posts/[id]/media`. Depuis la fiche d'un post au format carrousel, `StudioBridge` crée un carrousel lié à ce post (`createCarousel({ postId })`) ou l'ouvre. L'éditeur s'enregistre automatiquement (indicateur partagé `src/components/save-indicator.tsx`). Zone de texte : détectée dans l'espace libre du mockup (`detectFreeZone` dans `src/lib/mockup-zone.ts`, sur une version 64 px de l'image ; zone centrée préférée), tailles de caractères assorties (`styleForZone`) ; un nouveau carrousel reprend la mise en page du dernier carrousel au même mockup. IA : tâches `carouselSlides` (tout le carrousel) et `carouselSlide` (3 versions d'une slide), à partir de la description du post et de la place disponible (`textCapacity`), écrites pour le réseau choisi par les boutons de `carousel-ai.tsx` (`platform` du contexte, règles `CAROUSEL_PLATFORM_RULES` dans `tasks.ts`). 
- Fiche d'un post (`src/components/posts/post-editor.tsx`) : enregistrement automatique (800 ms après la dernière modification, un enregistrement à la fois, et avant fermeture ou passage à un autre post) ; un nouveau post n'est créé qu'à la première modification. Panneaux Contenu (médias, légende, notes) / Aperçu (`post-preview.tsx`) et Détails (`details-panel.tsx`) ; choix de la date avec `SchedulePicker`. Par réseau (`caption-section.tsx`) : légende (`customCaption`) et hashtags (`customHashtags`, sinon ceux du post via `platformHashtags`) personnalisables ; « Adapter » (tâche `adapt`) réécrit la légende avec les formules d'accroche et choisit les hashtags dans la limite du réseau.
- Fenêtres ouvertes depuis la fiche d'un post : les rendre à l'intérieur de `SheetContent` (sinon la page peut rester bloquée à la fermeture).
- Accès à internet (`src/server/web/`) : `playwright-core` pilote le Chrome installé sans fenêtre (`browser.ts` : lecture de pages, captures écran entier ou d'un bloc, réglages d'écran dans `CAPTURE_VIEWPORTS` de `src/lib/web.ts`), recherche Bing (`search.ts`, lecture des résultats dans `src/lib/web.ts`), captures rangées dans la médiathèque, catégorie « screenshot » (`captures.ts`, route `/api/web/capture`). Réglages `ai.web` (accès activé, site de la marque).
- Analyse du site (Marque › Identité, `site-analysis.tsx`) : route `/api/ai/site` (pages choisies par `pickSitePages`, tâche `siteSummary`), résumé dans `settings` (clé `site`, `meta.site`, `src/lib/ai/site.ts`) ajouté aux consignes de toutes les tâches via `BrandContext.site` (`getBrandContext` dans `src/server/ai/context.ts`). Appel d'une tâche + nouvel essai si le JSON est invalide : `runTask` (`src/server/ai/run-task.ts`).
- Assistant (`/assistant?chat=<id>`, `src/components/assistant/`) : discussions dans la table `assistant_chats` (messages en JSON, `ChatEntry`), route `/api/ai/chat` (NDJSON : texte, étapes, réponse). Si une réponse liste des idées sans l'outil, le bouton « Ajouter ces idées au tableau » les relève (tâche `extractIdeas`, `ExtractIdeas` dans `assistant-view.tsx`) en cartes `IdeaCards`. Outils du modèle (appels d'outils OpenAI de LM Studio) : `web_search`, `read_page`, `take_screenshot`, `propose_post_ideas` (définitions, lecture des arguments et consignes dans `src/lib/ai/chat.ts`, boucle dans `src/server/ai/agent.ts`).
- Images des slides du Studio : `slide.image` (capture de la bibliothèque, cadre navigateur / téléphone / carte, position) dans `src/lib/carousel.ts` (`imageFrameLayout`, `textZone` : le texte se place au-dessus de l'image), dessin des cadres dans `render-slide.ts`, choix dans `slide-image-picker.tsx`.
- Ton par réseau : consignes de l'assistant pour chaque réseau (ton, écriture, hashtags, bio), valeurs conseillées dans `DEFAULT_VOICES` (`src/lib/ai/platform-voice.ts`), réglables dans Marque › Identité (`platform-voice-form.tsx`, clé `ai.voices`, champ vide = valeur conseillée) ; envoyées via `BrandContext.voices` (`platformTips` dans `tasks.ts`, aussi dans les consignes de l'Assistant).
- Écrans de l'app : planche de captures d'une app web, réglée par espace dans `workspaces.json` (`appShots` : adresse, page de connexion, comptes de test, liste des écrans ; schéma `appShotsConfigSchema` dans `src/lib/app-shots.ts`), capture dans `src/server/web/app-shots.ts` (connexion, navigation par le routeur Nuxt si présent, bloc via `screenshotBlock` de `browser.ts`), route `/api/web/app-shots` (NDJSON), bouton « Écrans de l'app » dans la Médiathèque (si `meta.workspace.appShots`). Rangées en catégorie `app` (remplacées sur place, nom de fichier `app-<key>.png`), description en 2e ligne des notes. L'IA du Studio (`carouselSlides`, champ `screens`) choisit un écran par slide (`screen`), appliqué dans `carousel-ai.tsx` ; l'Assistant reçoit leurs titres.
- Bonnes pratiques Instagram (adaptées du pack MIT « instagram-agent-skill ») : 26 formules d'accroche (`src/lib/ai/hooks.ts`, `hookGuide()` dans les légendes, carrousels, idées et briefs vidéo), règles anti-IA (`src/lib/humanize.ts` : `HUMAN_WRITING_RULES` dans chaque prompt système, `cleanAiOutput`/`cleanAiCaption` sur toutes les réponses des tâches, `detectAiTells`), vérificateur de légende dans la fiche d'un post (`src/lib/caption-lint.ts`, règles par réseau tirées des skills dans `PLATFORM_LINT_RULES` : texte visible avant « plus », hashtags, liens, longueur), audit du profil Instagram sur 100 (grille `src/lib/ai/profile-rubric.ts`, tâche `profileAudit`, `components/accounts/profile-audit.tsx`). Instagram : 5 hashtags maximum.
- Rédaction IA : liberté par post (`posts.ai_mode`, `AI_MODES` dans `tasks.ts`, champ « Rédaction IA » des Détails) : « Ouverte » (défaut) autorise les connaissances générales sur le sujet, les faits sur la marque restant tirés du document de référence ; « Stricte » s'en tient à la marque (`buildSystemPrompt(…, { mode })`). Skills par réseau : guides GitHub copiés tels quels dans `brand/skills/` (sources et licences dans son README), fichiers choisis par réseau et usage (`PLATFORM_SKILL_FILES` dans `src/lib/ai/platform-skills.ts`, nettoyés et coupés à un budget), relus à chaque demande (`readPlatformSkills`, `src/server/ai/platform-skills.ts`), envoyés via `BrandContext.skills` dans `captions`, `rewrite`, `adapt`, `mediaAnalysis` et les tâches carrousel ; état dans Marque › Identité › Ton par réseau (`meta.platformSkills`).
- Recherches d'un post (section « Recherches » de la fiche, `src/components/ai/post-research.tsx`) : route `/api/ai/research` (NDJSON : progression, étapes, notes), boucle d'outils partagée avec l'Assistant (`runToolLoop` dans `src/server/ai/agent.ts`, seulement `web_search` et `read_page`, `researchTools`), consignes et sources dans `src/lib/ai/research.ts` ; notes sourcées stockées sur le post (`posts.research`, JSON `PostResearch`, modifiables), envoyées aux tâches via le champ `research` du contexte d'un post (`describePost`). Nécessite `ai.web.enabled`.
- Mise à jour des skills par réseau depuis GitHub : `npm run skills:update` (`scripts/update-skills.mjs`, liste dans `brand/skills/sources.json`), puis relire le diff. Les skills ne sont jamais réécrits à la main ni par l'IA.
- Création rapide d'un post (`MediaAssistant`, `src/components/ai/media-assistant.tsx`) : dès qu'un média est ajouté, on choisit réseaux et format sous les médias, puis « Rédiger le post » lance `mediaAnalysis`, remplit les champs vides (titre, légende, appel à l'action ; hashtags ajoutés) et, avec plusieurs réseaux, adapte la légende à chacun (tâche `adapt`, skills) sans toucher aux légendes déjà personnalisées. « Choisir moi-même » / « Voir les autres propositions » ouvrent le panneau détaillé.
- Mise en page « kicker » du Studio : par slide `kicker` et `source`, par image `label` et cadre `paper` (carte blanche) ; par carrousel `footer`, `pagination`, `gradientTop`, `halos` (`src/lib/carousel.ts`, dessin dans `render-slide.ts` : `drawBackground`, `drawFooter`). Valeurs proposées par le bloc `studio` de la charte (dont `kickers`, qui fait aussi écrire kicker et source à l'IA : `look` du contexte, `lookRules` dans `tasks.ts`).
- Guides d'un espace (`guides` dans `workspaces.json`, ex. leçons des posts publiés, règles de vérification des faits) : relus à chaque demande par `readWorkspaceGuides` (`src/server/workspace-guides.ts`), envoyés via `BrandContext.guides`.
